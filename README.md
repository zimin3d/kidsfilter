# kidsfilter — белый список сайтов для детских компьютеров на OpenWrt

Ограничивает интернет для выбранных устройств (по MAC-адресу): им доступны только сайты из белого списка.
Остальные устройства в сети работают как обычно. Управление — из LuCI: **Службы → Детский фильтр**.

- **Режимы:** «Только белый список»; «Обучение» — всё открыто, но каждый запрос записывается; «Выключен».
- **Обучение:** всё, что дети пытались открыть вне списка, собирается на странице «Обучение» — разрешается галочкой.
  Кнопка «Открыть на N минут» временно открывает доступ с записью (например, для нового сайта к урокам), потом закрывает сама.
- **Статистика:** по каждому ребёнку — топ сайтов, активность по часам и дням, доля запросов вне списка (до 30 дней).
  Журнал запросов в реальном времени и соединения, заблокированные по IP.
- **DNS для детей:** DNS роутера или семейный фильтр (Яндекс, Cloudflare, AdGuard) — только для детских устройств.
- **Страница блокировки:** вместо ошибки браузера — страница «Этот сайт закрыт» с адресом сайта
  (где это технически возможно, см. ниже).

## Требования

- OpenWrt **22.03 или новее** (проверено на 23.05, 24.10 и 25.12).
- `dnsmasq-full` вместо `dnsmasq` — установщик заменит его сам (см. «Что делает установщик»).
- LuCI — если её нет, ставится простая страница `http://<роутер>/cgi-bin/kidsfilter`.

## Установка

Скачайте проект: на GitHub — **Code → Download ZIP** (распакуйте в папку `kidsfilter`) или `git clone`.
Затем с компьютера в домашней сети (на роутере должен быть интернет):

```sh
scp -O -r kidsfilter root@192.168.1.1:/tmp/
ssh root@192.168.1.1 sh /tmp/kidsfilter/install.sh
```

Затем откройте LuCI → **Службы → Детский фильтр** (если пункта нет — обновите страницу или войдите заново).
После установки фильтр в режиме **«Обучение»**: ничего не блокируется, только записывается.
Повторный запуск `install.sh` обновляет программу, настройки, список и статистика сохраняются.

### Что делает установщик

- Если dnsmasq собран без nftset — заменяет его на `dnsmasq-full`, **безопасно**:
  сохраняет `/etc/config/dhcp` (в `/etc/kidsfilter/dhcp.backup`), всё нужное скачивает **до** удаления старого пакета,
  после замены проверяет, что DNS работает, а при любой ошибке возвращает прежний dnsmasq (без интернета) и настройки DHCP.
- Копирует файлы, добавляет задачи cron, включает службу `kidsfilter`.
- **Не меняет** настройки firewall, сети и основного dnsmasq. Правила фильтра — в отдельной таблице `inet kidsfilter`.

## Первая настройка

1. **Дети:** LuCI → Детский фильтр → «Дети». В «Устройствах в сети» впишите имя у нужного компьютера и нажмите «Добавить».
   - В Windows **отключите «Случайные аппаратные адреса»** для домашнего Wi-Fi, иначе MAC будет меняться.
   - Если компьютер подключается и по кабелю, и по Wi-Fi — добавьте оба устройства с одним именем.
   - Устройство, с которого вы сейчас управляете роутером, помечено «управляет роутером» — фильтр не даст случайно
     сделать его детским (иначе вы потеряете доступ к роутеру с него).
2. **2–3 дня обучения:** дети пользуются компьютером как обычно.
3. **Разбор:** страница «Обучение» — отметьте нужное (домен или «весь сайт» `*.example.com`) и нажмите «Разрешить».
4. **Включите** на странице «Обзор» режим **«Только белый список»**.
5. Когда нужен новый сайт: «Открыть на 20 мин» → ребёнок открывает сайт → «Обучение» → разрешить нужные домены.

## Командная строка

| Команда | Что делает |
|---|---|
| `kidsctl status` | режим, счётчики, кто из детей в сети |
| `kidsctl mode enforce\|learn\|off` | сменить режим |
| `kidsctl open <мин>` / `close` | временно открыть доступ (в режиме enforce) |
| `kidsctl pending [дней]` | домены вне белого списка |
| `kidsctl allow <домен\|ссылка\|IP/сеть>…` | разрешить (с поддоменами) |
| `kidsctl deny <домен>…` | убрать из списка (закрывается сразу) |
| `kidsctl list` | белый список |
| `kidsctl stats [дней]` | статистика по детям |
| `kidsctl log` | запросы в реальном времени |
| `kidsctl blocked` | соединения, заблокированные по IP |
| `kidsctl dns [router\|yandex\|cloudflare\|adguard\|<IP>…]` | DNS для детей |
| `kidsctl blockpage [on\|off]` | страница «Сайт закрыт» (по умолчанию включена) |
| `kidsctl kid add <имя> <MAC>` / `kid del` / `kid list` / `kid devices` | детские устройства |
| `kidsctl restart` | перезапустить фильтр |

Файлы настроек — `/etc/kidsfilter/`: `whitelist.txt` (можно править руками, затем `kidsctl restart`), `kids.list`,
`kidsfilter.conf` (LAN-интерфейсы, порт, сроки хранения). Сохраняются при обновлении прошивки.

## Как это работает

1. DNS-запросы детских устройств (порт 53 на любой сервер, в том числе 8.8.8.8) перехватываются
   и направляются на отдельный dnsmasq (порт 5300). Основной dnsmasq роутера не меняется.
2. Этот dnsmasq отвечает только на домены из белого списка, а адреса разрешённых доменов заносит в наборы nftables.
   На остальные домены он отвечает адресом роутера (страница блокировки) или «домен не существует», если страница выключена.
3. Соединения детей разрешены только к адресам из этих наборов. Поэтому не помогут ни чужой DNS,
   ни DNS-over-HTTPS, ни VPN, ни прямые IP.
4. Детям закрыт доступ к самому роутеру (LuCI, SSH), кроме DNS, DHCP и ping.

### Надёжность

- Правила проверяются перед загрузкой и применяются атомарно; действуют только на трафик с LAN-интерфейсов,
  поэтому не могут задеть сам роутер, WAN, PPPoE или VPN-туннели.
- Перезагрузка firewall фильтр не трогает. Если таблицу кто-то удалил (`nft flush ruleset`) или детский DNS упал —
  фильтр восстанавливается сам в течение минуты.
- Если детский DNS не работает, дети остаются без интернета, а не без фильтра (безопасный отказ).
  Остальные устройства и сам роутер при этом не затрагиваются.
- Задачи cron не копятся, прерванная операция не оставляет «зависших» блокировок и не теряет данные.

### Сколько памяти занимает

Всё, что растёт со временем, ограничено, так что ни оперативную память, ни флеш фильтр не заполнит:

| Что | Где | Предел |
|---|---|---|
| Статистика | RAM | 1/32 памяти роутера, не больше 8 МБ; сначала удаляются самые старые дни. Один день — не больше половины предела: тысячи одноразовых адресов (трекеры, CDN) сворачиваются в базовый домен |
| Журнал запросов | RAM | разбирается каждые 10 минут, а при росте больше 2 МБ — в ту же минуту |
| Поток запросов | RAM | не больше 100 DNS-запросов в секунду с одного устройства — защита от «зацикленной» программы (`DNS_RATE`) |
| Разрешённые адреса (nftables) | RAM ядра | больше 20 000 — ночью наборы очищаются и заполняются заново (`ALLOW_MAX`) |
| Прочие служебные файлы | RAM | сотни строк, адреса для `deny` — до 20 000 строк |
| Копия статистики | флеш | раз в сутки и при перезагрузке, сжатая, не больше 1 МБ. На флеше всегда остаётся не меньше 512 КБ свободного места; если места мало, сохраняются только последние дни (`SAVE_MAX_KB`, `SAVE_RESERVE_KB`) |

Текущие размеры видны в LuCI → Детский фильтр → Обзор. Все пределы настраиваются в `/etc/kidsfilter/kidsfilter.conf`.
Журналы и статистика доступны только root: это история запросов детей.

### Страница блокировки

В режиме «Только белый список» HTTP-запросы детей к неразрешённым адресам перенаправляются на маленький веб-сервер
на роутере (отдельный `uhttpd`, порт 5380, слушает только в LAN). Он показывает страницу «Этот сайт закрыт» с адресом
сайта и подсказкой попросить родителей. Сам адрес уже попал на страницу «Обучение» — его можно разрешить галочкой.
Включить или выключить: LuCI → Детский фильтр → Обзор → «Страница блокировки», или `kidsctl blockpage on|off`.

**Где страница появится, а где нет.** Сейчас почти все сайты работают по HTTPS, и подменить защищённую страницу
нельзя: браузер увидит чужой сертификат и покажет предупреждение. Поэтому:

- **Появится**, если сайт открыли по `http://` или ребёнок набрал адрес вручную (`vk.com`, `game.ru`): браузер сначала
  пробует https, получает мгновенный отказ и переходит на http, а там уже страница блокировки.
- **Не появится** по ссылке `https://…` (например, из поиска) и на сайтах, которые разрешают только HTTPS
  (Google, YouTube, соцсети, банки — у них включён HSTS). Там браузер покажет свою ошибку
  («Соединение сброшено» / «Не удаётся получить доступ к сайту»), причём сразу, без долгого ожидания.
- Программы и игры страницу не показывают, у них просто нет соединения, как и раньше.

Свою страницу можно положить в `/etc/kidsfilter/blocked.html` (затем `kidsctl restart`). Адрес сайта на ней
подставляет JavaScript из адресной строки, пример — `/usr/share/kidsfilter/blocked.html`. Если `uhttpd` не установлен,
фильтр работает как раньше, без страницы (`kidsctl blockpage` покажет причину).

Проверки «есть ли интернет» в Windows, Android, Firefox и Apple есть в белом списке по умолчанию. Если их убрать,
устройство примет страницу блокировки за страницу входа в Wi-Fi сети и будет её показывать.
У старых установок список не обновляется автоматически, поэтому для iPhone, iPad и Mac добавьте `kidsctl allow captive.apple.com`.

## Если что-то пошло не так

- **Выключить фильтр:** LuCI → Детский фильтр → «Выключен», или `kidsctl mode off`.
- **Устройство по ошибке стало «детским» и потеряло доступ к роутеру:** зайдите с другого устройства
  и уберите его на странице «Дети» (или `kidsctl kid del <MAC>`).
- **Журнал:** `logread | grep kidsfilter`; состояние: `kidsctl status`.
- **Удалить полностью:** `sh /tmp/kidsfilter/uninstall.sh` (настройки и статистика остаются в `/etc/kidsfilter`,
  dnsmasq-full остаётся — он полностью заменяет обычный dnsmasq).

## Ограничения

- **Общие IP у CDN.** Разрешение работает по IP, а на одном адресе Cloudflare/Google может быть много сайтов.
  Разрешив сайт за CDN, технически можно попасть и на другой сайт с того же адреса. Для обычного ребёнка это неважно.
- **Права администратора у ребёнка** позволяют сменить MAC и выйти из-под фильтра — дайте ребёнку обычную учётную запись.
  Мобильный интернет или чужой Wi-Fi роутер, понятно, не контролирует.
- **Ускорение (flow offloading)** в настройках firewall: уже открытые соединения обходят проверку, поэтому «Закрыть»
  и переход в «Только белый список» не обрывают их (новые блокируются). Если это важно — отключите offloading.
- В режиме **«Обучение»** ребёнок может включить в браузере DNS-over-HTTPS, и его запросы не попадут в журнал.
  В режиме «Только белый список» это невозможно.
- Сложные сайты (YouTube, Google) требуют десятков доменов (`googlevideo.com`, `ytimg.com`, `gstatic.com`, …) —
  их удобно собирать через «Открыть на N минут».
- Устройства в гостевой сети фильтруются, только если её интерфейс добавлен в `LAN_IF` (`/etc/kidsfilter/kidsfilter.conf`).
